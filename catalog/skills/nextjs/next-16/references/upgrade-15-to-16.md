# Upgrading a Next.js 15 app to 16

Checked against `next@16.4.3`. "Measured" means it was built and served with `next build` and
`next start` on 16.4.3; everything else is from the upgrade guide bundled in
`node_modules/next/dist/docs/01-app/02-guides/upgrading/version-16.md`.

## Order of work

1. Install exact versions together and commit the lockfile: `next`, `react`, `react-dom`,
   `@types/react`, `@types/react-dom`. Node 20.9+ and TypeScript 5.1+ are required.
2. Run `next build`. It fails fast on removed APIs (TypeScript errors) and prints `⚠` lines for
   deprecated config. Fix all of them; the codemods (`npx @next/codemod@canary upgrade latest`,
   `next-async-request-api`, `middleware-to-proxy`) cover the mechanical part.
3. Then grep for what the build does not catch (below). These are the silent changes.
4. Prove behaviour with `next start`: request each page type, every webhook, every sitemap, and one
   optimised image, and compare with production.

## Grep for the silent ones

```sh
rg -n "revalidateTag\(" app lib src                          # each call needs a profile chosen by semantics
rg -n -e generateSitemaps -e generateImageMetadata app src    # id and params became Promises
rg --files -g "*opengraph-image.*" -g "*twitter-image.*" -g "*icon.*" app src
rg -n "quality=\{?\d" app src components                    # needs images.qualities
rg -n "src=\"/[^\"]*\?" app src components                  # local images with query strings
rg -n "scroll-behavior" app src styles
rg -n "UnsafeUnwrapped|cookies\(\)\.|headers\(\)\.|draftMode\(\)\." app src lib
rg -n "params\.|searchParams\." app src                     # sync reads that still type-check
```

## Async request APIs: sync access is gone

```tsx
// 15 compatibility code (often produced by the 15 codemod)
import { cookies, type UnsafeUnwrappedCookies } from 'next/headers'
export default function Layout({ children }) {
  const lang = (cookies() as unknown as UnsafeUnwrappedCookies).get('lang')?.value
}

// 16
import { cookies } from 'next/headers'
export default async function Layout({ children }: LayoutProps<'/'>) {
  const lang = (await cookies()).get('lang')?.value
}
```

Measured: `UnsafeUnwrappedCookies` no longer exists (`TS2305`). Props are not checked for you: a page
typed `({ params }: { params: { slug: string } })` that reads `params.slug` type-checks, builds and
renders an empty value, because `params` is a Promise. Typing props with `PageProps<'/docs/[slug]'>`
turns that into a type error. In a Client Component that receives
`params` as a Promise, unwrap with React's `use(params)`. `PageProps<'/route'>`,
`LayoutProps<'/route'>` and `RouteContext<'/route'>` are global helpers generated by `next build`,
`next dev` and `next typegen`.

## `revalidateTag` now takes a profile

```ts
// 15: expire now, next request waits for fresh data
revalidateTag('catalog')

// 16, same behaviour
revalidateTag('catalog', { expire: 0 })     // Route Handler / webhook
updateTag('catalog')                        // Server Action (read-your-own-writes)

// 16, different behaviour: stale-while-revalidate
revalidateTag('catalog', 'max')             // next request gets the OLD data, refresh runs in background
```

Measured on 16.4.3, without Cache Components (`unstable_cache` with `tags`, dynamic page) and with
them (`'use cache'` + `cacheTag`): after `'max'` or `'hours'` the first request returns the old
content and a later one the new; after `{ expire: 0 }`, `revalidatePath()` or the forced one-argument
call the first request is fresh. Both the upgrade guide and the Cache Components migration guide show
`revalidateTag('posts')` becoming `revalidateTag('posts', 'max')`; that is a behaviour change, fine
only when one stale response is acceptable.

## Metadata files: ids and params are Promises

```ts
// app/docs/sitemap.ts
export async function generateSitemaps() {
  return [{ id: 0 }, { id: 1 }]
}

// 15
export default async function sitemap({ id }: { id: number }) {
  const offset = id * 10_000 // 16: NaN, the sitemap silently comes out empty
}

// 16
export default async function sitemap({ id }: { id: Promise<string> }) {
  const offset = Number(await id) * 10_000
}
```

Measured: the 15 version type-checks and builds on 16.4.3 and serves sitemaps whose URLs contain
`NaN` (or nothing, if the id feeds `slice`). The same applies to `params` and `id` of the default
export in `opengraph-image`, `twitter-image`, `icon` and `apple-icon`; `generateImageMetadata` still
receives plain `params`.

## next/image defaults

| Setting | 15 | 16 | What to do |
| --- | --- | --- | --- |
| `qualities` | any 1-100 | `[75]` | list every `quality` prop you use, e.g. `[75, 90]`. Measured: `quality={90}` silently renders `q=75` |
| `domains` | supported | deprecated | `remotePatterns: [{ protocol: 'https', hostname: 'cdn.example.com' }]` or `[new URL('https://cdn.example.com/**')]` |
| local `src` with a query string | allowed | needs `localPatterns: [{ pathname: '/assets/**', search: '?v=1' }]` | add the pattern |
| `minimumCacheTTL` | 60 s | 14400 s | set it back if upstream images change often |
| `imageSizes` | starts at 16 | starts at 32 | add 16 back only if you serve 16px images |
| `maximumRedirects` | unlimited | 3 | raise or set 0 |
| local IP upstreams | allowed | blocked | `dangerouslyAllowLocalIP: true` only on private networks |

## middleware.ts to proxy.ts

```ts
// proxy.ts (was middleware.ts)
import { type NextRequest, NextResponse } from 'next/server'

export function proxy(request: NextRequest) {           // was: export function middleware
  if (!request.cookies.has('sid')) {
    const login = new URL('/sign-in', request.url)
    login.searchParams.set('returnTo', request.nextUrl.pathname)
    return NextResponse.redirect(login)
  }
  return NextResponse.next()
}

export const config = { matcher: ['/billing/:path*'] }    // no `runtime`: proxy is always Node.js
```

Measured: `middleware.ts` still runs and prints "The "middleware" file convention is deprecated";
having both files fails the build ("Both middleware file … and proxy file … are detected");
`runtime: 'edge'` in `proxy.ts` fails the build. Apps that must stay on the Edge runtime keep
`middleware.ts` for now. Rename config flags too (`skipMiddlewareUrlNormalize` →
`skipProxyUrlNormalize`).

## Config

```ts
// 15
const config: NextConfig = {
  experimental: { turbopack: { resolveAlias: { '~*': '*' } }, dynamicIO: true },
  eslint: { ignoreDuringBuilds: true },
  serverRuntimeConfig: { apiBase: 'https://api.example.com' },
}

// 16
const config: NextConfig = {
  turbopack: { resolveAlias: { '~*': '*' } },
  // cacheComponents: true, partialPrefetching: true  -- only if you adopt the model (section 4 of SKILL.md)
}
// lint with the ESLint or Biome CLI; read process.env on the server (after `await connection()`
// if it must be read at request time rather than build time)
```

Measured: `experimental.turbopack` and `eslint` both print an invalid-config `⚠` and fail type
checking. From the guide: `next build` uses Turbopack, and a custom `webpack()` function fails the
build unless you run `next build --webpack` (or plugins add one without you noticing).

## Routing

- Every parallel route slot needs `default.tsx` (measured: "Parallel route slots cannot render the
  same URLs"). Return `null` to keep the 15 behaviour of rendering nothing.
- Strict route matching is on: pages that no complete route reaches fail the build. The escape hatch
  is `deprecated.looseRouteMatching: true` (temporary).
- `next dev` writes to `.next/dev`, so `next dev` and `next build` can run at the same time.
- Global `scroll-behavior: smooth` is no longer overridden during navigation; add
  `data-scroll-behavior="smooth"` to `<html>` to get the 15 behaviour.
- AMP, `next lint`, `devIndicators.appIsrStatus/buildActivity/buildActivityPosition`,
  `unstable_rootParams` and `next/legacy/image` (deprecated) are gone or going.
